# OBD Outlander — Android-приложение

Kotlin + Jetpack Compose клиент для ELM327-адаптеров (Bluetooth Classic SPP и BLE).  
Профили: **Mitsubishi Outlander GF/GG (2012–2021)**, **Hyundai Creta (2018)**.  
Пакет: `com.chuikoff.obd`. Версия: **1.11.0** (versionCode 13).

## Возможности

- Подключение к ELM327 по **Bluetooth Classic (SPP)** и **BLE (Nordic UART)**
- Живые показания:
  - **Температура ОЖ** — SAE Mode 01 PID `05` (формула `A − 40`, °C)
  - **Температура снаружи** (Outlander) — **только AWC 210D** (приборка; байт 8 `(I/2)−40` + фильтр «как у панели»); без Cond/climate/SAE
  - **Температура CVT** (Outlander) — Mode 21 `2103`@7E1, **байт N** (OUT-CLUB OUT3), построчная сборка ISO-TP, карточка «Диагностика CVT» с логом
  - **Температура коробки** (Creta) — ScanGauge `21A0`@7E1 → `21A0`@7E0 → Mode22 `01A0` (reject `0xFF`/`0xFE`)
- Вкладка **Ошибки**: Mode 03 / 07; сброс Mode 04 — при `7F` «Сброс отклонён ЭБУ (условия)», cleared только при чистом `44`
- **Android Auto** (projected Car App): статус + ОЖ / CVT / снаружи из live-снимка телефона
- Выбор профиля автомобиля (расширяемый реестр)

## Открыть в Android Studio

1. Установите Android Studio Hedgehog+ (или новее) с Android SDK 34.
2. **File → Open** → выберите каталог `obd-android/`.
3. Дождитесь синхронизации Gradle (Wrapper уже включён).
4. При необходимости укажите SDK в `local.properties`:
   ```
   sdk.dir=/path/to/Android/Sdk
   ```
5. Запуск: выберите конфигурацию `app` → Run.

Минимальные требования: **minSdk 26**, **target/compileSdk 34**, JDK 17+.

## Установка debug APK

1. Включите на телефоне «Режим разработчика» и **Отладку по USB** (или разрешите установку из неизвестных источников для APK-файла).
2. Скопируйте `obd-android-debug.apk` на устройство.
3. Откройте файл и установите.
4. При первом запуске разрешите **Bluetooth** (и геолокацию на Android ≤ 11 для сканирования).

Сборка из исходников:

```bash
export ANDROID_HOME=/path/to/Android/Sdk
./gradlew assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

## Архитектура

```
connection/     ObdTransport ← BluetoothClassicTransport, BleTransport
elm327/         Elm327Client (flush + prepareStandardObdBus + DTC), Elm327Parser
vehicle/        VehicleProfile, Registry, OutlanderGfGgProfile, Creta2018Profile
sensors/        CoolantTempSensor, CvtTempSensor, OutlanderAmbientTempSensor, AmbientTempSensor
data/           ObdLiveData (shared snapshot for AA + prefs)
car/            ObdCarAppService / Session / Screen (Android Auto)
viewmodel/      ObdViewModel + StateFlow
ui/             Compose: Connect / Readings / Ошибки / Profile
```

Поток данных: UI → ViewModel → Elm327Client → ObdTransport → адаптер → разбор → SensorReading → UI (+ ObdLiveData → Android Auto).

## Как добавить модель / датчик

### Новый профиль автомобиля

1. Создайте класс `MyCarProfile : VehicleProfile`.
2. Реализуйте `sensors()` и при необходимости `cvtTempCommand()`.
3. Зарегистрируйте экземпляр в `VehicleProfileRegistry`.

### Новый датчик

1. Реализуйте `SensorDefinition` (метод `read(Elm327Client)`).
2. Добавьте датчик в `sensors()` нужного профиля.

## Вкладка «Авто» — паспорт автомобиля (1.11.0)

Читается **по кнопке «Обновить»** (не в опросе): опрос датчиков на время чтения ставится на паузу, затем
возобновляется; все запросы идут через тот же `Elm327Client` (mutex + авто-восстановление), шина готовится как на
вкладке «Ошибки» (`ATSH7DF`/`ATAR`), после чтения восстанавливается `ATSH7E0`. Пробы неподдерживаемых PID (NO DATA)
не засчитываются в счётчик восстановления. Работает для Outlander и Creta.

- **VIN** (Mode 09 PID 02): ISO-TP сборка через `Elm327Parser.assemble`; проверка длины 17 и отсутствия I/O/Q;
  локальная расшифровка: производитель/страна по WMI (маленькая таблица: JM*/JA3/JA4/JA7, KMH/KM8/KMF, Z94, TMA, Z8T),
  модельный год (10-й символ, «или −30 лет»), код завода (11-й символ).
- **Calibration ID** (09 04), **CVN** (09 06), **имя ЭБУ** (09 0A) — если ЭБУ поддерживает (по маске `0900`).
- **Поддерживаемые PID** Mode 01: `0100`/`0120`/`0140`/`0160`… по цепочке бита «следующий диапазон», с названиями
  частых PID (остальные — hex), сводка «Всего: N».
- **Готовность мониторов** (`0101`): MIL, число DTC, катализатор / подогрев кат. / EVAP / вторичный воздух / A/C /
  O2-датчик / подогрев O2 / EGR / пропуски / топливная система / компоненты — готов / не готов / н/д
  (для дизельных — свой набор).
- Каждый пункт падает отдельно («не поддерживается» / «нет ответа ЭБУ»). Результат кэшируется в SharedPreferences
  (`passport_cache`) и показывается офлайн с временем; кнопки «Копировать» / «Поделиться» отдают текст.
- Состояние lock-up/TCC пока не включено. Тесты: `PassportTest`.

## Устойчивость канала ELM (1.10.1)

- Обмен команда/ответ целиком под одним mutex; если предыдущий обмен не дошёл до prompt `>`
  (таймаут/отмена опроса), перед следующей командой шлётся одиночный CR и вычитывается хвост —
  иначе ELM отвечает `STOPPED`.
- 5 подряд плохих ответов на запросы данных (`STOPPED`, `BUFFER FULL`, `CAN ERROR`, `NO DATA`, пусто, `?`)
  → flush + `ATZ` + полная инициализация как при подключении, с нарастающей паузой 3→60 с;
  на экране «переподключение… (попытка N)» вместо тихих прочерков.
- Диагностика CVT: кнопки в одну строку с весами, без вложенной карточки.
- 1.10.0 менял только `ReadingsScreen.kt`; изменений в опросе/подключении не было.

## Экран «Показания» (1.10.0)

Карточки показывают только название и цветное число (❄ для гололёда), «нет данных» при пустом значении,
тусклое число при удержанном. Вся техника (шкала цветов, источник, RAW, сырой датчик/скорость/заметка
фильтра снаружи, карточка «Диагностика CVT» с формулой, 2102, копировать/поделиться) — в сворачиваемом
блоке «Диагностика» под карточками (по умолчанию свёрнут). Android Auto без изменений (только значения).

## Цвета температур (1.9.0)

Одна шкала `ui/TempColorScale.kt` для всех карточек (все профили) и для Android Auto:
цветное число + светлая подложка карточки (alpha 0.12), строка-легенда под числом; удержанное
(тусклое) значение остаётся тусклым; при «—» цвета нет. Полоса выбирается по **показанному**
(округлённому как `%.0f`) числу, поэтому число и цвет всегда совпадают.

| Датчик | Полосы |
|---|---|
| CVT / коробка (без изменений) | `<20° синий · 20–99° зелёный · ≥100° красный` |
| ОЖ | `<70° синий · 70–104° зелёный · 105–109° оранжевый · ≥110° красный` |
| Снаружи (значение фильтра) | `≤−10° мороз (фиолетовый) · −9…+3° гололёд (синий, ❄ перед числом) · +4…+15° прохладно (бирюзовый) · +16…+25° комфорт (зелёный) · +26…+30° жарко (оранжевый) · >30° жара (красный)` |

Цвета: фиолетовый `#7E57C2`, синий `#1E88E5`, бирюзовый `#0097A7`, зелёный `#43A047`,
оранжевый `#FB8C00`, красный `#E53935` — читаемы в светлой и тёмной теме.
Android Auto: значения ОЖ / CVT / снаружи окрашены `ForegroundCarColorSpan` (`CarColor.createCustom`);
головное устройство может показать стандартный цвет, если сочтёт контраст недостаточным.
Тесты: `TempColorScaleTest` (границы 69/70, 104/105, 109/110; −10/−9, 3/4, 15/16, 25/26, 30/31; CVT 19/20, 99/100).

## Температура снаружи (Outlander) — только AWC 210D

- **AWC CAN (приборка / cluster outdoor):**  
  Pre `ATSH7B6`, `ATFCSH7B6`, `ATFCSD30080A`, `ATFCSM1`, `ATCRA7B7` → `210D`  
  Decode (1.8.0): **строго байт I (index 8)** → `(I/2)−40`; кадр собран без дыр и содержит ≥ 9 байт данных,
  байт `00`/`FF` и значения вне −39.5…70 °C отбрасываются. Старые запасные индексы `5,6,7,4,9` удалены —
  это были костыли под баг парсера до 1.7.0.  
  Post restore: `ATSH7E0` / `ATCRA7E8` …
- **Без fallbacks:** Cond `2113` / climate `2111` / SAE `0146` удалены.
- ISO-TP: с 1.7.0 ответ собирается построчно (`Elm327Parser.assemble`), строка длины и префиксы `N:` снимаются только в своей строке.
- Подпись источника: `AWC 210D (приборка), фильтр как у панели`; caveat: `AWC 210D — датчик с приборной панели`.

### 1.8.0 — фильтр как у приборной панели (`AmbientDisplayFilter`)

Байт 8 — это **сырой** датчик в бампере. На холостых он прогревается от радиатора и асфальта:
в сессии 08.10 сырой рос 19 → 24 °C, а панель всё время показывала 19 °C. Ни один байт `210D`
не держит постоянные 19 (постоянные байты 2/5/10 = `04`/`18`/`FF` по шкале в 19 не ложатся) —
отфильтрованное значение панели в этом кадре не передаётся, поэтому фильтр повторяет её логику:

- **вниз — сразу**: сырой ниже показанного → показываем сырой;
- **вверх — медленно**: не быстрее **1 °C за 60 с**, не выше сырого и **только при скорости ≥ 20 км/ч**
  (SAE `010D`); время стоянки «в запас» не копится;
- **без скорости** (`010D` не отвечает): рост только если сырой выше показанного **10+ мин подряд**;
- **горячий перезапуск**: последнее показанное значение и время хранятся в SharedPreferences
  (`ambient_filter`); новая сессия в пределах **2 ч** стартует с него, если сырой выше, иначе с сырого.
- `010D` запрашивается только когда сырой выше показанного, не чаще раза в 5 с (один короткий запрос
  на уже восстановленном заголовке 7E0); после 3 неудач подряд — раз в минуту. Опрос CVT не замедляется.
- Экран: крупно — значение фильтра; под ним `датчик: 24 °C (сырой, греется на стоянке)` (+ скорость);
  строка источника и RAW остаются. Битый кадр — держим показанное (тускло) до 10 опросов.
- Android Auto получает отфильтрованное значение.
- Тесты: `AmbientFilterTest` (реальные 9 кадров сессии: при 0 км/ч показ = 19, сырой до 24;
  при 60 км/ч +1 °C/мин; падение мгновенно; без скорости — 10 мин; горячий перезапуск).

## Температура CVT (Outlander) — 1.7.0

Нет официального SAE PID; источник — **OUT-CLUB, Torque `OUT3.csv`** (TCM `7E1` → ответ `7E9`):
`2103`: A=(A−2)·32 перв. шкив, B=(B−2)·64 втор. шкив, C·32 обороты, D скольжение, E/100 передаточное,
F ускорение, G педаль, H/I/J моменты, K коэф. момента, L/M давления, **N = count температуры масла CVT**.

### Что было сломано (до 1.6.0 включительно)

1. **Наш парсер терял байты.** `clean()` склеивал строки ответа ELM и потом удалял префиксы
   кадров регэкспом `\d+:`. На склейке `…EC40` + `2:` регэксп съедал `402:` — т.е. **все
   «цифровые» hex-ниблы в конце предыдущего кадра**. Отсюда «разная длина» и «сдвинутые поля»,
   а не из-за адаптера. Скрин-дампы R1/R2/R3 и AWC точно воспроизводятся этим багом (unit-тест).
2. **1.6.0 брала не тот байт.** «Маркер 85» — это и есть N (count), он одинаков во всех
   кадрах (0x85 = 133). «Count от хвоста» брал следующий байт O (0x20/0x2B/0x3B), который за
   одну минуту прыгал 32→43→59 — это не температура.

### Как сейчас

- Pre: `ATAT1`, `ATST32`, `ATSH7E1`, `ATFCSH7E1`, `ATFCSD30080A`, `ATFCSM1`, `ATCRA7E9`; запрос `2103`
- Построчная сборка ISO-TP: строка длины (`014`), кадры `0:`/`1:`/`2:` (и формат с заголовками
  `7E9 10 14 …`/`7E9 21 …`), проверка последовательности кадров, обрезка паддинга по длине.
- Кадр с потерянным ISO-TP кадром (дыра) **отбрасывается**; N берётся только по индексу 13
  корректно собранного кадра. Байт 00/FF — невалиден.
- Формула (переключатель в карточке «Диагностика CVT», сохраняется):
  - **OUT3 полином** (по умолчанию): `2.344e-9·N⁵ − 1.387e-6·N⁴ + 3.193e-4·N³ − 0.03501·N² + 2.302·N − 36.6`
  - **CVT8: N − 55** (строка «(Out3 CVT8) CVT Temperature» из того же OUT3.csv)
  - Пример N=133: полином 65 °C, N−55 78 °C. Проверка: после ночи стоянки CVT ≈ улица.
- Сглаживание: медиана 3 валидных; на битом кадре держим последнее (тусклое) максимум 5 опросов,
  потом «—» с реальной ошибкой.
- **Диагностика CVT**: последний кадр (статус сборки, N, обе формулы, байт O для сравнения,
  обороты шкивов), RAW как есть, опционально запрос `2102` (байт E — напряжение датчика),
  кнопки **Копировать / Поделиться** — последние 50 ответов текстом.
- Тесты: `./gradlew testDebugUnitTest` (`app/src/test/.../CvtParsingTest.kt`, `AmbientFilterTest.kt`, `TempColorScaleTest.kt`, `Elm327RecoveryTest.kt`, `PassportTest.kt`).

Охлаждающая жидкость (**PID 05**) — стандарт SAE; перед чтением восстанавливается engine filter.

## Hyundai Creta (2018)

- Coolant: SAE `0105`
- Gearbox oil («Температура коробки») — **community / ScanGauge CANSF**:
  1. Mode **`21A0`**, header **`7E1`** (TXD `07E121A0`), °C = `A−40` (MTH≈FFD8)
  2. Alt Mode **`21A0`**, header **`7E0`** (TXD `07E021A0`)
  3. Last resort Mode 22 DID `01A0` (still reject filler)
  - **`0xFF` / `0xFE` = invalid filler**, not temperature (was the cause of fake **215°C**)
  - Sanity window **−20…150 °C**
  - Mode22 parse uses `normalizeObdHex` / `6201A0` marker on messy ISO-TP RAW
- Ambient: **SAE `0146` only** — note `может отличаться от приборки`; **no intake `010F` as outdoor**; TODO cluster PID
- Многие Creta 2018 — **6AT A6GF1**, не CVT.

## Стабильность в поездке (1.5.0)

- Poll loop: try/catch per cycle — **не гасит опрос** при сбое; soft recover (flush + restoreEngineEcuFilter)
- Live-показания для ОЖ/снаружи; **CVT**: median + stale-hold (≤5 опросов) при битом ISO-TP кадре (1.7.0)
- Classic BT: детект мёртвого сокета → soft recover / одноразовый `reconnectSameDevice`
- Foreground service **`ObdMonitorService`** («OBD опрос») + PARTIAL_WAKE_LOCK против Doze
- Цвет значений CVT / ОЖ / снаружи — см. «Цвета температур (1.9.0)»
- Профиль: `Версия приложения: VERSION_NAME (VERSION_CODE)`
- `ATAT1` adaptive timing; skip redundant `ATSH` если header уже выставлен

## Диагностика (DTC)

Перед Mode 03 / 07 / 04 вызывается `prepareStandardObdBus()`:
`ATH0`, `ATAL` (если поддерживается), `ATSH7DF` (functional broadcast), `ATAR` (или `ATCRA000000` при ERROR).

- Mode `03` / `07` — сохранённые / pending
- Mode `04` — сброс с AlertDialog
- Ответ с **`7F`** (без `44`): «Сброс отклонён ЭБУ (условия)» — коды **не** сбрасываются в UI
- Чистый **`44`**: claim cleared + перечитать
- **NODATA / пустой список = успешное «кодов нет»**

## Android Auto

- Car App Library `androidx.car.app:app:1.4.0`, категория **IOT** (не NAVIGATION).
- Экран показывает статус подключения и последние ОЖ / CVT / снаружи из `ObdLiveData`.
